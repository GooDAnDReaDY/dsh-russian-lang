# Архитектура плагина

## Две половины Cordis-плагина

Плагин состоит из двух изолированных, но согласованных частей:

1. **Серверная половина (`lib/index.js`)**:
   - Работает в Node.js / Cordis контексте DSH.
   - Экспортирует метаданные плагина, схему `cordis.patch.yml`.
   - Регистрирует HTTP API эндпоинты (`/api/dsh-russian-lang/...`) для отдачи словарей ядру и клиенту.
   - Обеспечивает фоновый контроль дрейфа словарей ядра через `upstream_check.py`.

2. **Клиентская половина (`lib/client.js`)**:
   - Собирается из исходного шаблона `lib/client.template.js` с помощью `build.py`.
   - Бандл оптимизирован по размеру (< 160 KiB) и не использует тяжеловесных сторонних библиотек.
   - Регистрируется в интерфейсе через слот `settings.plugin.item`.
   - Внедряется в `window.LocaleRuntime`, вызывая `addLanguage('ru', 'Русский')` и управляя `setLocale('ru')`.

## Структура словарей

```
ru/                     # Словари ядра DSH (58 пространств имён, 2442 ключа)
ru-plugins/             # Словари плагинов экосистемы (65+ плагинов, 6140+ ключей)
plugins-en.json         # Английские эталонные снимки плагинов для проверки дрейфа
upstream/core-en.json   # Английский эталонный снимок ядра DSH
mt-registry.json        # Хэш-реестр машинного перевода и проверенных fallback-значений
```

## Защита DOM от ложного перевода

Плагин соблюдает строгий контракт невмешательства в защищённый контент:
- Атрибут `data-no-translate` и класс `.no-translate` полностью блокируют замену текста внутри узла.
- Блоки терминального вывода, сырого кода (`<pre><code>`), markdown-превью и пользовательского ввода защищены от искажения.
